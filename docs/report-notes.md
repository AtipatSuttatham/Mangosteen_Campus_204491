## ก้อน 1 — เข้าสู่ระบบ / ข้อมูลส่วนตัว (UC-01, UC-02 · PR #10–#19)

**ทำอะไร:**
- เข้าสู่ระบบด้วยอีเมล **หรือ** รหัสนักศึกษา/พนักงาน ; บอก "บัญชีถูกระงับ" เฉพาะเมื่อรหัสผ่านถูก
- บัตรผ่าน 2 ใบ: access 15 นาที (ในหน่วยความจำ) + refresh 7 วัน (httpOnly cookie, **ใช้ได้ครั้งเดียว**)
- ออกจากระบบแท็บหนึ่ง → ทุกแท็บออก ; ถูกให้ออกกลางคัน → กลับหน้าเดิมหลัง login
- หน้าข้อมูลส่วนตัว: แก้ชื่อ / อีเมล, เปลี่ยนรหัสผ่าน (อุปกรณ์อื่นหลุด**ทันที**), รูปประจำตัว (ย่อ ≤ 512×512 บันทึก WebP ลบข้อมูลแฝง GPS)
- โครงหน้าจอ sidebar + เมนูลิ้นชักบนมือถือ

**เขียนในรายงาน** (จาก `database.md` §11 v2.3):
- UC-02: ระบุกฎรหัสผ่าน 4 ข้อ และข้อจำกัดรูป (JPG / PNG / WebP ≤ 2 MB)
- ความปลอดภัยที่ทำเกินรายงาน: บัตรใช้ครั้งเดียว + ลายนิ้วมือรหัสผ่าน (`pwd`) ในบัตร

**การทดสอบที่น่าเล่า:** ทดสอบบนเบราว์เซอร์เจอว่า refresh token ใบเดียวกันยื่นพร้อมกันแล้วผ่านทั้งคู่ → แก้ให้ผ่านแค่คำขอแรก (ขั้น 1.4.1) ; ต้องล็อกการแลกบัตรข้ามแท็บ (Web Locks)

## ก้อน 2 — จัดการบัญชีผู้ใช้ (UC-04 · PR #20–#26)

**ทำอะไร:**
- รายชื่อผู้ใช้: ค้นหา / กรองบทบาท-สถานะ / แบ่งหน้า 20 ; เพิ่ม / แก้ไข / รีเซ็ตรหัส / ระงับ-เปิดใช้งาน (ยืนยันก่อนระงับ)
- รหัสผ่านชั่วคราว: พิมพ์เองหรือกด "สุ่มรหัส" 12 ตัว
- กันล็อกตัวเอง: ระงับ / เปลี่ยนบทบาทตัวเองไม่ได้ + ต้องเหลือผู้ดูแลระบบอย่างน้อย 1 คน (ล็อกแถวกันกดพร้อมกัน)
- 🆕 **นำเข้า CSV 3 ขั้น**: ตรวจทั้งไฟล์ก่อน (แสดงแถว / คอลัมน์ / ปัญหา) → ถูกทุกแถวจึงสร้างใน transaction เดียว → ดาวน์โหลดไฟล์รหัสผ่านได้ครั้งเดียว ; รับ UTF-8 และ TIS-620 (Excel ไทย) ; ≤ 500 แถว
- AuditLog ฝั่งเขียน: จดสร้าง / แก้ไข (เฉพาะช่องที่เปลี่ยน) / ระงับ ; ไม่เก็บรหัสผ่าน

**เขียนในรายงาน** (จาก §11 v2.4):
- UC-04: เพิ่ม "สร้างบัญชีจาก CSV" (ขั้นตอนตรวจก่อนนำเข้า + รูปแบบไฟล์ `email, student_or_staff_id, first_name, last_name, role`), "รีเซ็ตรหัสผ่าน", กติกากันล็อกตัวเอง
- เหตุผลเชิงวิศวกรรมที่น่าเล่า: รหัสชั่วคราวจาก CSV เข้ารหัสแบบเบาก่อน (500 คน × 0.4 วินาทีเกินเวลารอบนเครื่องฟรี) แล้วระบบเปลี่ยนเป็นแบบเต็มเองตอน login ครั้งแรก

## ก้อน 3 — รายวิชา / การลงทะเบียน (UC-07, UC-08, UC-15 ส่วนเข้าร่วม · PR #28–#44)

**ทำอะไร:**
- ผู้สอนสร้างรายวิชา (ปี / ภาคเริ่มที่ภาคปัจจุบัน) ; ผู้ดูแลระบบสร้างแทนโดยเลือกผู้สอน
- สถานะ: ยังไม่เผยแพร่ → เผยแพร่ → ปิด ; ยกเลิกเผยแพร่ได้ ; **เปิดคืนได้เฉพาะผู้ดูแลระบบ** ; ลบได้เฉพาะวิชาที่ยังไม่เผยแพร่และไม่เคยมีผู้เรียน
- รหัสเข้าร่วม 8 ตัว (ตัดตัวที่สับสน 0 O 1 I L) ; สร้างใหม่ / ปิดได้ ; กรอกผิดทุกกรณีได้ข้อความเดียว (กันเดาข้อมูล) ; จำกัด 10 ครั้ง/นาที
- เพิ่มผู้เรียน 2 วิธี: ค้นหาทีละคน / 🆕 วางรายการหรือเลือกไฟล์ (.xlsx / .csv / .txt อ่านในเบราว์เซอร์) + 🆕 **ตารางตรวจรายการก่อนเพิ่ม** ; ถอน / เพิ่มกลับ (คะแนนเดิมยังอยู่) ; คนที่ถูกถอนใช้รหัสเข้าร่วมกลับเองไม่ได้
- หน้าจัดการรายวิชาของผู้ดูแลระบบ: ทุกวิชาในระบบ + ตัวกรอง + เปลี่ยนผู้สอน + แถบส้ม "จัดการแทนผู้สอน"
- ป้ายรหัสวิชา (`CourseBadge`) 3 สถานะ × 3 ขนาด รองรับรหัสยาวถึง 20 ตัว ; คำอธิบายรายวิชาแบบ Markdown

**เขียนในรายงาน** (จาก §11 v2.5, v2.6):
- ตาราง 4.4 + UC-07: **รหัสวิชาไม่ซ้ำภายในภาคเดียวกัน** (ต้องแก้), ลบรายวิชา, ยกเลิกเผยแพร่ / เปิดคืน, ผู้สอนของวิชาที่ผู้ดูแลระบบสร้าง
- UC-08: เพิ่มผู้เรียนหลายคนจากไฟล์ + ตรวจรายการก่อนเพิ่ม ; ผู้เรียนที่ถูกถอนกับรหัสเข้าร่วม (เปลี่ยนจากสเปกเดิม W5)

**การทดสอบที่น่าเล่า:** ทดสอบบนจอจริงของผู้ใช้ (1536×639) + มือถือจำลอง 390 / 320px → ปรับ 3 รอบ เช่น ป้ายรหัสวิชาเมื่อรหัสยาว, ตารางตรวจรายการบนจอเตี้ย, ผลของการกดในแท็บตั้งค่าให้ขึ้นในส่วนที่กด ; ปรับโครงสร้างโค้ดแท็บตั้งค่าให้แก้ง่าย (PR #42) + ตรวจรูปแบบโค้ดด้วย Prettier ใน CI (PR #43)

## ก้อน 4 — หน่วยการเรียน / เนื้อหา / อัปโหลดไฟล์ (UC-09, UC-15 ส่วนดูเนื้อหา · PR #45–#62)

**ทำอะไร:**
- หน่วยการเรียน: เพิ่ม / แก้ / ลบ / เรียง ↑ ↓ / เผยแพร่
- เนื้อหา 6 ชนิด: ข้อความ (Markdown + แท็บดูตัวอย่าง), เอกสาร, รูปภาพ, เสียง, วิดีโอ (ไฟล์ หรือ YouTube ที่ระบบรู้เอง), ลิงก์
- อัปโหลดหลายไฟล์ ≤ 20 ไฟล์ต่อครั้ง ลากวางได้ แถบความคืบหน้ารายไฟล์ ไฟล์ที่ไม่ผ่านข้ามไปแล้วรายงาน ; ระบบตั้งชนิดและหัวข้อเองจากไฟล์
- ตรวจเนื้อไฟล์จริง (magic bytes) ไม่ใช่แค่นามสกุล ; ไม่รับ .html / .svg ; เอกสาร/รูป/เสียง ≤ 20 MB, วิดีโอ ≤ 100 MB
- 🆕 สวิตช์ "ให้ผู้เรียนดาวน์โหลดได้" ต่อไฟล์ (`Content.allow_download`) — ใช้ได้เฉพาะไฟล์ที่เบราว์เซอร์เปิดดูได้
- หน้าบทเรียนของผู้เรียน (วิดีโอ / รูปขยาย-ย่อ, ลิงก์ไฟล์ชั่วคราวที่ขอใหม่เองเมื่อหมดอายุ) + ตัวอย่าง "ที่ผู้เรียนจะเห็น" ในแท็บผู้สอน
- ผู้ดูแลระบบดูเนื้อหาได้อย่างเดียว (ตามรายงานตาราง 3.1)

**เขียนในรายงาน** (จาก §11 v2.7):
- ตาราง 4.6: เพิ่ม field `allow_download` ; อธิบาย `file_url` ว่าเก็บ**ตำแหน่งไฟล์** ไม่ใช่ลิงก์เต็ม (§11 v2.1 "ควรแก้")
- ชนิด / ขนาดไฟล์ที่รับ และเหตุผลที่ไม่รับ .html / .svg (ความปลอดภัย)

**การทดสอบที่น่าเล่า:** ทดสอบต่อเนื่องทุกบทบาท 13 ลำดับใน Chrome (ขั้น 4.8) ; ปัญหาที่เจอระหว่างทดสอบ เช่น ดาวน์โหลดได้ชื่อไฟล์สุ่ม (แก้ด้วย `dev_media.py`), ไฟล์ .txt ภาษาไทยอ่านไม่ออก (ระบุ `charset=utf-8`), ปุ่มท้ายแถวล้นการ์ดบนมือถือ 320px, การเข้าถึงด้วยแป้นพิมพ์ (โฟกัสหลุดเมื่อปุ่มถูก disabled)
