| เรื่อง | ข้อตกลง |

| กันล็อกตัวเอง | ผู้ดูแลระบบ**ระงับหรือเปลี่ยนบทบาทของตัวเองไม่ได้** และระบบต้องเหลือผู้ดูแลระบบที่ใช้งานได้อย่างน้อย 1 คน (รหัส `cannot_modify_self` / `last_active_admin`) — backend ตรวจเสมอ ; "คนสุดท้าย" เกิดได้เฉพาะกรณี admin 2 คนกดพร้อมกัน จึงตรวจแบบล็อกแถวในฐานข้อมูล ; หน้าจอแค่ซ่อนปุ่มในแถวตัวเอง (ป้าย "คุณ") |
| รหัสผ่านชั่วคราว | ผู้ดูแลระบบ**พิมพ์เอง + ปุ่ม "สุ่มรหัส"** (สุ่มในหน้าเว็บด้วย `crypto.getRandomValues` 12 ตัว ตัดตัวที่สับสนง่าย, แสดง/คัดลอกได้) — ใช้ทั้งตอนสร้างบัญชีและรีเซ็ตรหัส ; backend ตรวจกฎรหัสผ่าน 4 ข้อเสมอ ; รีเซ็ตแล้วอุปกรณ์เดิมของผู้ใช้หลุดทันที (ลายนิ้วมือ `pwd`) |
| นำเข้า CSV | **ต้องถูกทั้งไฟล์จึงนำเข้า**: ตรวจก่อน (ยังไม่บันทึก) → มีแถวผิดแสดงรายการ "แถว / คอลัมน์ / ปัญหา / ค่าในไฟล์" ให้แก้แล้วอัปโหลดใหม่ ; ถูกทุกแถว → สรุปจำนวนตามบทบาท → กด "นำเข้า" → ตรวจซ้ำแล้วสร้าง**ทุกแถวใน transaction เดียว** ; เลขแถวนับแบบ Excel (แถวหัวตาราง = 1) ; ไฟล์ ≤ 1 MB และ ≤ 500 แถว ; เลือกไฟล์แล้วตรวจทันที |
| CSV สร้างได้แค่ผู้สอน/ผู้เรียน | แถว `role = admin` ถือว่าผิด (`csv_admin_not_allowed`) — ผู้ดูแลระบบสร้างทีละคนเท่านั้น |
| การเข้ารหัสไฟล์ CSV | รับทั้ง **UTF-8 (มี/ไม่มี BOM)** และ **TIS-620/cp874** (Excel ไทย) ตรวจอัตโนมัติ ; อ่านไม่ได้ → `csv_unreadable` ; ไฟล์ตัวอย่างและไฟล์ผลลัพธ์เป็น UTF-8 มี BOM (Excel เปิดแล้วอ่านภาษาไทยได้) |
| ไฟล์รหัสผ่านหลังนำเข้า | backend ส่งรหัสกลับ**ครั้งเดียว**ในผลลัพธ์ของการนำเข้า → หน้าเว็บสร้างไฟล์ CSV ให้ดาวน์โหลด (server ไม่เก็บรหัส) ; ดาวน์โหลดได้เฉพาะตอนยังอยู่หน้านั้น ; ออกจากหน้าก่อนดาวน์โหลด → **เบราว์เซอร์ถามยืนยันก่อนออก** (ผู้ใช้เลือกแบบ ก) |
| ยืนยันก่อนระงับ | ระงับบัญชีต้องยืนยันผ่าน **`ConfirmDialog`** (คอมโพเนนต์ใหม่ ใช้ซ้ำในก้อนอื่น — โฟกัสปุ่ม "ยกเลิก" ก่อน) ; ปุ่มยืนยันเป็น **ปุ่มแบบใหม่ `danger` สีแดงทึบ** (ผู้ใช้เลือกแบบ ก) ; เปิดใช้งานทำทันทีไม่ถาม |
| หน้าจอ | ฟอร์มเพิ่ม/แก้ไข/รีเซ็ต = หน้าต่างกลางจอ (มือถือ = เต็มจอ) ; นำเข้า CSV = หน้าแยก 3 ขั้น ; แบ่งหน้า 20 รายการด้วยปุ่ม "ก่อนหน้า / ถัดไป" ; ค้นหาชื่อ/รหัส/อีเมล + กรองบทบาท/สถานะ ; แถวตัวเองไม่มีปุ่มรีเซ็ตรหัส (ใช้หน้าข้อมูลส่วนตัว) ; ปุ่ม "จำลองมุมมอง" ยังไม่แสดงจนถึงก้อน 9 |
| AuditLog (ขั้น 2.2) | เขียนผ่าน `audit.services.log_action()` จุดเดียว **เรียกเองในจุดที่ต้องบันทึก** (ไม่ใช้ marker `Auditable` แบบอัตโนมัติ เพราะต้องรู้ผู้กระทำจากคำขอ และการแก้ข้อมูลตัวเองตาม UC-02 ไม่ต้องบันทึก) ; สร้าง = ค่าที่ตั้ง, แก้ไข = เฉพาะช่องที่เปลี่ยน, ระงับ = `{"is_active": [true, false]}`, รีเซ็ตรหัส = `{"password": ["***", "***"]}` ; **ไม่เก็บรหัสผ่านเด็ดขาด** ; บันทึกแล้วแก้/ลบไม่ได้ ; หน้า `/admin/` ดูได้อย่างเดียว |
| API จัดการบัญชี (ขั้น 2.3) | ที่อยู่ `/api/v1/admin/users/…` (รายละเอียด `docs/api.md` §7) ; **เปลี่ยนบทบาทแล้วไม่บังคับออกจากระบบ** (ผู้ใช้เลือกแบบ ก 2026-10-12 — backend อ่านบทบาทจากฐานข้อมูลทุกคำขอ สิทธิ์เก่าจึงใช้ไม่ได้ทันที) ; **ผู้ดูแลระบบแก้ชื่อ/อีเมล/รหัสของตัวเองผ่านหน้าจัดการผู้ใช้ = จด AuditLog** (ผู้ใช้เลือกแบบ ก — กฎ "ทุกอย่างในหน้าจัดการผู้ใช้ถูกจด" ; หน้าข้อมูลส่วนตัว UC-02 ยังไม่จด) ; รีเซ็ตรหัสตัวเองไม่ได้ (`cannot_modify_self` — ใช้หน้าข้อมูลส่วนตัว) ; Claude เลือก (มาตรฐาน): แบ่งหน้า `{count, next, previous, results}` ด้วย `?page=N` ใช้ทั้งระบบ, ค้นหารวมชื่อเต็ม, รหัสนักศึกษาไม่บังคับ, บัญชีที่สร้างผ่าน API ไม่ได้ `is_staff`, ทำซ้ำสถานะเดิม = สำเร็จแต่ไม่จด |

| หน้ารายชื่อผู้ใช้ (ขั้น 2.5) | ที่อยู่ **`/users`** (ไม่ใช้ `/admin/users` เพราะตอน deploy `/admin/` เป็นหน้า Django admin บนโดเมนเดียวกัน) ; เมนู "จัดการผู้ใช้" + ยามหน้าประตูเฉพาะผู้ดูแลระบบ ; **ปุ่มเพิ่ม / นำเข้า / แก้ไข / รีเซ็ต / ระงับ ยังไม่แสดงจนกว่าจะทำงานได้** (ผู้ใช้เลือกแบบ ก 2026-10-13 — กฎเดียวกับเมนู "แสดงเฉพาะสิ่งที่ทำเสร็จแล้ว") ; Claude เลือก (มาตรฐาน): ตัวกรองเก็บในที่อยู่ของหน้า, ค้นหลังหยุดพิมพ์ 0.3 วินาที, "ทั้งหมด N" / "พบ N" ตามการกรอง, ขอหน้าที่ไม่มี → กลับหน้า 1, สลับตาราง ↔ การ์ดที่ 1024px (จุดเดียวกับ sidebar) ; คอมโพเนนต์ใหม่ `Select`, `SearchInput`, `Pagination` + `StatusBadge` ขนาด `sm` + token `line-soft` |
