# การตัดสินใจเรื่อง deploy (ผู้ใช้ยืนยันแล้ว 2026-10-10 — **เบื้องต้น เปลี่ยนได้**)

> ย้ายมาจาก `CLAUDE.md` (2026-11-22) โดย**คัดลอกตรงตัว** — เป็นการตัดสินใจที่ผู้ใช้ยืนยันแล้ว มีลำดับความสำคัญเท่ากับ `CLAUDE.md` (ชนะรายงานเสมอ)
> กติกาที่ใช้ข้ามก้อนสรุปไว้ใน `CLAUDE.md` หัวข้อ "กติกาที่ใช้ข้ามก้อน" — ถ้าแก้ข้อในไฟล์นี้ที่ถูกสรุปไว้ ให้แก้ที่นั่นด้วย

เงื่อนไขของผู้ใช้: **ฟรี**, **ไม่มีบัตรเครดิต** (มีแค่บัตรเติมเงินของ TrueMoney — Oracle / Google Cloud / Koyeb ไม่รับ), **เว็บต้องเปิดตลอด**, คณะไม่มีเซิร์ฟเวอร์ให้

| เรื่อง | ข้อตกลง |
|---|---|
| แผนหลัก | **Render** แผนฟรี, ภูมิภาค Singapore — **service เดียว** (Docker): Django ส่งหน้าเว็บ React ที่ build แล้วเอง → frontend/backend **โดเมนเดียวกัน** (cookie ของ refresh token ทำงานปกติ ไม่ต้องตั้ง CORS) ; ห้ามสร้าง service ฟรีตัวที่ 2 ใน workspace เดียวกัน (ชั่วโมงฟรี 750/เดือน พอสำหรับเปิดตลอดแค่ 1 ตัว) |
| ฐานข้อมูล | **Supabase** แผนฟรี (PostgreSQL 500 MB), ภูมิภาค Singapore — โปรเจกต์ถูกหยุดถ้าไม่มีการใช้ฐานข้อมูล 1 สัปดาห์ → กันด้วย UptimeRobot ; ไม่ใช้ Postgres ฟรีของ Render (หมดอายุ 30 วัน) |
| ไฟล์ | **Backblaze B2** (ฟรี 10 GB, ไม่ต้องใช้บัตร), ภูมิภาค **US West** (เลือกตอนสมัคร เปลี่ยนไม่ได้) — bucket แบบ **Private** + ลิงก์ชั่วคราว (presigned URL) ; ตอนตั้งค่าต้องตั้ง **Lifecycle "Keep only the last version"** (ไม่งั้นไฟล์ที่ถูกแทนที่ยังกินพื้นที่) และ **Caps & Alerts = $0** ; กุญแจจำกัดให้ใช้ได้แค่ bucket เดียว |
| กันเว็บหลับ | **UptimeRobot** แผนฟรี (ใช้ได้เฉพาะงานไม่เชิงพาณิชย์ — โปรเจกต์การศึกษาเข้าเงื่อนไข) เรียก `/api/health/` **ทุก 5 นาที** → Render ไม่หลับ (หลับเมื่อว่าง 15 นาที) + Supabase มีการใช้งาน + แจ้งเตือนทางอีเมลเมื่อเว็บหรือฐานข้อมูลล่ม |
| ตัวเลือกสำรอง | **Azure for Students** (เครดิต $100 ไม่ต้องใช้บัตร) — ผู้ใช้**สมัครแล้ว 2026-10-10** เครดิตหมดอายุประมาณ **2027-10-10** ; **ยังไม่สร้างบริการใด ๆ** จนถึงขั้น deploy ; ใช้แบบ VM เครื่องเดียว (Caddy + Django) ต่อ Supabase + B2 เหมือนแผนหลัก — จะลองและตัดสินตอนใกล้ deploy |
| เวลา deploy | **ครั้งแรกหลังก้อน 10 เสร็จ** (ตาม `PROJECT_SCOPE.md` ส่วน "หลังก้อน 10") |
| ตัดสินตอน deploy | deploy อัตโนมัติทุกครั้งที่ merge หรือสั่งเอง ; ยืนยันภูมิภาค ; ชื่อเว็บ `xxx.onrender.com` ; ความถี่สำรองข้อมูล ; **ทบทวนการจำกัดการลองรหัสผ่าน** (MVP ไม่จำกัด — เว็บจริงใครก็เข้าหน้า login ได้) ; **ทบทวนตัวนับจำกัดการลองรหัสเข้าร่วม** (ขั้น 3.4 — เก็บในหน่วยความจำของแต่ละ process ; ถ้ารันหลาย process / ต้องการนับรวม ให้ใช้ cache กลาง) ; **แบ่งไฟล์หน้าเว็บตามหน้า (code splitting)** (ผู้ใช้เลือกแบบ ห1 หลัง PR #40 — `pnpm build` เตือนไฟล์ JS หลักเกิน 500 kB มาตั้งแต่ก่อนขั้น 3.8 : 779 kB → 801 kB หลังขั้น 3.8, หลังบีบอัด 233 kB ; แก้ด้วยการโหลดหน้าแบบ lazy ใน `router.tsx`) ; **ตรวจ Dependabot อีกครั้ง โดยเฉพาะ `minimatch`** (ผู้ใช้เลือกแบบ ฒ1 หลัง PR #34 — แจ้งระดับปานกลาง ใช้เฉพาะตอนพัฒนาผ่าน ESLint ไม่อยู่ในเว็บที่ deploy ; รุ่นแก้คือ 11 ซึ่ง ESLint ยังไม่รองรับ) ; **วัดการอัปโหลดวิดีโอ 100 MB บน Render จริง** (ขนาดคำขอ / เวลารอ — ก้อน 4) ; **ทดสอบลิงก์ไฟล์หมดอายุบน B2 จริง** (ขั้น 4.7 — ตอนพัฒนาไฟล์อยู่ในเครื่องไม่หมดอายุ จึงทดสอบด้วยการจำลอง: เปิดหน้าไว้เกิน 1 ชั่วโมงแล้วกดเปิด / ดาวน์โหลด / เล่นวิดีโอ) ; **จำกัดขนาดคำขอก่อนรับไฟล์** (ผู้ใช้เลือกแบบ กผ3 หลังตรวจขั้น 4.3 — ตอนนี้ Django รับไฟล์ทั้งก้อนลงดิสก์ชั่วคราวก่อนตัวตรวจจะบอกว่าใหญ่เกิน ; ดิสก์ของ Render ฟรีมีจำกัด → ตรวจ `Content-Length` เทียบเพดานวิดีโอก่อนอ่านไฟล์ + ตัวนับระหว่างรับไฟล์ `StopUpload` ; พร้อมกันนั้นเก็บ 2 เรื่องเล็ก: test เนื้อหาถูกลบระหว่างเปลี่ยนไฟล์, ข้อความไทยของรหัส 415 — เรื่อง `allow_download` ของเนื้อหาที่ไม่มีไฟล์แก้แล้วพร้อม กพ1) ; เขียน `docs/deployment.md` (ขั้นตอนจริงทีละคำสั่ง) — **เช็กเงื่อนไขแผนฟรีของทุกเจ้าใหม่อีกครั้งก่อนลงมือ** (เปลี่ยนบ่อย) |
