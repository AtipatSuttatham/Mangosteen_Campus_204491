# การตัดสินใจก้อน 1 — เข้าสู่ระบบ / ข้อมูลส่วนตัว (ผู้ใช้ยืนยันแล้ว 2026-10-10)

> ย้ายมาจาก `CLAUDE.md` (2026-11-22) โดย**คัดลอกตรงตัว** — เป็นการตัดสินใจที่ผู้ใช้ยืนยันแล้ว มีลำดับความสำคัญเท่ากับ `CLAUDE.md` (ชนะรายงานเสมอ)
> กติกาที่ใช้ข้ามก้อนสรุปไว้ใน `CLAUDE.md` หัวข้อ "กติกาที่ใช้ข้ามก้อน" — ถ้าแก้ข้อในไฟล์นี้ที่ถูกสรุปไว้ ให้แก้ที่นั่นด้วย

| เรื่อง | ข้อตกลง |
|---|---|
| เครื่องมือฝั่งหน้าเว็บ | **React Router** (หลายหน้า) + **TanStack Query** (ดึง/แคชข้อมูลจาก API — ทำงานบน `apiFetch()`) + **React Hook Form** (ฟอร์ม) |
| บัญชีถูกระงับ | บอกว่า "ถูกระงับ" **เฉพาะเมื่อกรอกรหัสผ่านถูก** — รหัสผิดได้ข้อความรวมเหมือนกรณีอื่น |
| จำกัดการลองรหัสผ่าน | **ไม่จำกัด**ใน MVP — ทบทวนตอน deploy (อยู่ในรายการ "ตัดสินตอน deploy") |
| รหัสผ่าน | ไม่บังคับเปลี่ยนรหัสชั่วคราวตอน login ครั้งแรก ; กฎมาตรฐานของ Django 4 ข้อ (≥ 8 ตัว, ไม่ใช่รหัสยอดนิยม, ไม่เป็นตัวเลขล้วน, ไม่คล้ายชื่อ/อีเมล) ; เปลี่ยนรหัสต้องกรอกรหัสเดิม → **อุปกรณ์อื่นออกจากระบบทั้งหมด** |
| แก้อีเมล | ไม่ต้องกรอกรหัสผ่าน ; ตรวจซ้ำ/รูปแบบ ; อีเมลเก็บเป็นตัวพิมพ์เล็กเสมอ |
| รูปประจำตัว | **JPG / PNG / WebP ≤ 2 MB** → ย่อให้ไม่เกิน 512×512 แล้วบันทึกเป็นไฟล์ใหม่ (ลบข้อมูลแฝง เช่น GPS) ; ไม่มีครอป ; ไม่มีรูป → ตัวอักษรย่อชื่อ ; (ขั้น 1.7) บันทึกเป็น **WebP เสมอ** ชื่อไฟล์สุ่ม, ภาพเกิน 25 ล้านพิกเซลปฏิเสธ (กันกินหน่วยความจำ) |
| เปลี่ยนรหัสผ่าน → อุปกรณ์อื่นออก**ทันที** (ขั้น 1.7) | ผู้ใช้เลือกแบบ ก 2026-10-11: ใส่ "ลายนิ้วมือของรหัสผ่าน" (`pwd`) ในบัตร แล้วเทียบทุกคำขอ (`accounts/authentication.py`) — ไม่ใช่แค่รอบัตรผ่านชั่วคราวหมดอายุ 15 นาที ; ผลพลอยได้: ผู้ดูแลระบบรีเซ็ตรหัส (ก้อน 2) → อุปกรณ์เดิมหลุดทันที |
| เมนู sidebar | แสดง**เฉพาะหน้าที่ทำเสร็จแล้ว** — เพิ่มเมนูทีละก้อน |
| wireframe ที่ต้องเสนอก่อน (ขั้น 1.3) | หน้าเข้าสู่ระบบบนมือถือ, หน้าข้อมูลส่วนตัว, โครงหน้าจอบนมือถือ, หน้าแรกชั่วคราวหลัง login |
| หลายแท็บ / ออกจากระบบ (ขั้น 1.4) | ออกจากระบบในแท็บหนึ่ง → **ทุกแท็บไปหน้าเข้าสู่ระบบทันที** ; ถูกให้ออกกลางคัน → หน้าเข้าสู่ระบบพร้อมข้อความ "หมดเวลาการใช้งาน" แล้วพากลับหน้าเดิมหลัง login ; หน้าทดสอบสุขภาพระบบเดิมย้ายไป `/dev/health` (เฉพาะโหมดพัฒนา) ; ที่อยู่ที่ไม่มีจริง → พากลับหน้าแรก |
| บัตรสมาชิก (refresh token) | **ใช้แลกได้ครั้งเดียว** — แลกแล้วได้ใบใหม่ ใบเดิมขึ้นบัญชีดำ (กันบัตรที่ถูกขโมยใช้ได้นาน) ; **ยื่นพร้อมกันหลายคำขอ ผ่านแค่คำขอแรก** (ผู้ใช้เลือกแบบ ก 2026-10-11 — ไม่ใช้แบบ "เจอใช้ซ้ำแล้วออกทุกเครื่อง" เพราะเน็ตกระตุกจะทำให้เครื่องอื่นหลุดโดยไม่จำเป็น) ; 1 บัญชีใช้หลายเครื่องพร้อมกันได้ (แต่ละเครื่องมีบัตรของตัวเอง) |
| หน้าข้อมูลส่วนตัว (ขั้น 1.8) | **ลบรูปทันที ไม่ถามยืนยัน** (ผู้ใช้เลือกแบบ ก 2026-10-11 — อัปโหลดใหม่ได้ทุกเมื่อ) ; บันทึกสำเร็จ → ป้ายเขียว "บันทึกแล้ว" / "เปลี่ยนรหัสผ่านแล้ว" อยู่จนพิมพ์แก้ใหม่ ; ชื่อ/รูปเปลี่ยนทั่วหน้าจอและทุกแท็บทันที ; หน้าเว็บตรวจชนิด/ขนาดรูปและ "รหัสผ่านไม่ตรงกัน" ก่อนส่ง (backend ตรวจซ้ำเสมอ) |
| บัญชีทดลอง | คำสั่ง `seed_dev_users` (ทำงานเฉพาะ `DEBUG=True`) — อีเมล `@example.com`, ชื่อ/รหัสสมมติ, รหัสผ่านสุ่มแสดงบนหน้าจอครั้งเดียว ; **ผู้ดูแลระบบทดลองเป็น superuser** (ผู้ใช้เลือกแบบ ค 2026-11-25 — เดิมได้แค่ `is_staff` จึงเข้าหน้า `/admin/` ได้แต่ขึ้น "You don't have permission to view or edit anything" เพราะ Django ให้ดูตารางเฉพาะ superuser หรือคนที่ได้สิทธิ์รายตาราง) ; บัญชีเดิมที่ยังไม่เป็น superuser ได้สิทธิ์ครบเมื่อรันคำสั่งซ้ำ ไม่ต้องล้างฐานข้อมูล ; ทางเลือกที่ไม่เลือก: แก้เฉพาะในเครื่อง (แบบ ก — คนที่ติดตั้งใหม่เจอปัญหาเดิม), สร้าง superuser แยก (แบบ ข — มีบัญชีผู้ดูแลระบบเกินมาในหน้าจัดการผู้ใช้) ; superuser แก้ตารางผู้ใช้ใน `/admin/` ได้โดยไม่จด AuditLog — ยอมรับได้เพราะคำสั่งนี้ใช้เฉพาะเครื่องพัฒนา |
